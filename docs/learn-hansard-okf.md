# Learn OKF 0.3 with Hansard

Start with a real question. Ask what Parliament said about the Synergy programme, follow an exact contribution link and then open the timeline. Try the Railways Bill to see how a different question follows dates, people and stages. [Phone demonstration](mobile-demonstration.md) · [November in Parliament](https://chris-page-gov.github.io/okf-hansard/november/) · [Railways Bill example](https://chris-page-gov.github.io/okf-hansard/demo.html?example=railways-bill)

## What OKF 0.3 gives you

The Open Knowledge Format is a convention for organising text files so people and tools can read the same descriptions and evidence. Open the bundle's `index.md` to find the title, scope, declared version and links to its records. A record with a `type` in its YAML frontmatter is an OKF **concept**. The frontmatter is the structured header between the `---` lines. The rest is ordinary Markdown for humans to read. A concept might represent an individual parliamentary contribution, a Bill, an office or a subject. A subdirectory index provides a way to browse its contents. [Hansard OKF index](https://chris-page-gov.github.io/okf-hansard/november/okf/index.md) · [Pinned OKF 0.3 specification](https://github.com/open-knowledge-format/open-knowledge-format/blob/527e81aff55992be21507e97004286789126f88c/SPEC.md)

| Feature | What to try in Hansard | Why it helps |
| --- | --- | --- |
| Discoverable bundle root | Open the Markdown index or follow it from the [machine directory](https://chris-page-gov.github.io/okf-hansard/november/hansard.json). | A reader can find scope and entry points before loading records. |
| Typed concepts and links | Open the [Railways Bill evidence](https://chris-page-gov.github.io/okf-hansard/okf/railways-bill.md). Look at its header and follow a source. | A reader can distinguish kinds of records and resolve their references. |
| Provenance and dates | Compare the official record linked from a concept, the capture dates and the recorded verification in [coverage](https://chris-page-gov.github.io/okf-hansard/november/coverage.json). | Readers can check the source and determine which capture was used. |
| Verification, status and freshness | Inspect any `verified`, `status`, `generated` or `stale_after` fields the record actually declares. The published coverage and publication receipt have their own meanings. | A check on a release does not give every concept a human review. Unknown review or freshness remains unknown. |
| Attested Computations | Read the specification's fields for parameters, executor, receipt and attester. The Hansard counts and deterministic checks in this project are not examples of a declared OKF Attested Computation. | Where a producer implements this feature, a reader can check that a specific value comes from the defined computation and its attestation. |
| Best-effort reading | Read the fields a client understands and follow readable links. Report evidence missing from the routes the client can use. | A reader can still learn from plain Markdown, earlier records and recognised fields of an extended profile. |

## What Hansard adds with OKF+

This repository uses **OKF+** for the OKF core material and an explicitly versioned domain profile. The profile describes which parliamentary relationships can be asserted and what evidence an assertion carries. A **graph** is a collection of records and directed relationships between them. For example, a contribution can link to the person identified as its speaker or to a concept whose name was matched in its text. Each assertion supplies evidence for the relationship it describes. A textual match supports “mentioned”. It cannot by itself establish identity, support, causation or a commitment. [Domain profile](../profile/domain.yaml) · [Profile being published](../profile/hansard-domain-v2.json)

**YAML-LD** expresses linked data in YAML syntax. **JSON-LD** is a JSON representation of linked data. A context maps terms to stable identifiers so software can compare the meaning of relationships. The [full graph](https://chris-page-gov.github.io/okf-hansard/november/graph/okf-explorer.json) uses a descriptor and small files called **shards**. Explorer can follow a locator to the records or relationships it needs. The [compact core example](https://chris-page-gov.github.io/okf-hansard/november/core-walkthrough.html) demonstrates Reading OKF 0.3; that compact descriptor has zero graph relationships. A **timeline** orders dated records. A **facet** filters them by a property such as House, speaker, proceedings or legislation.

**A snapshot** identifies a specific captured and indexed collection. Check its coverage before comparing answers. A **source anchor** is a link to the exact contribution inside the official record when the source provides one. Some historical references resolve only to the debate. A **digest** is a content fingerprint that tells you whether two files contain the same bytes. An evidence receipt says which inputs and checks apply. A digest match gives integrity against a known digest. Trust in the publisher and verification of the source still matter. [How discovery and provenance fit together](okf-discovery.md) · [How the project builds and checks them](maintainer-guide.md)

## Learn the parliamentary terms

| Term | Meaning and what to look for |
| --- | --- |
| Hansard | The official edited report of proceedings. The bundle retains the official name, location or anchor of the source it used. [About Hansard](https://hansard.parliament.uk/about) |
| House of Commons, House of Lords and Westminster Hall | The two Houses of the UK Parliament each have recorded proceedings. Westminster Hall is a further venue for Commons debates. [Westminster Hall debates](https://www.parliament.uk/about/how/business/debates/westminster-hall-debates/) |
| Sitting, section and contribution | A sitting is a period when a House meets. A section groups items by business or debate. A contribution is an individual text-bearing item counted by the capture, such as a question, answer, speech or intervention. A day can have no sitting. |
| Statement, written question and written ministerial statement | A minister can give a statement and answer questions in the House. Written questions and answers are recorded apart from spoken business. A written ministerial statement publishes a minister's statement in writing. |
| Division, stage and reading | A division is a recorded vote. A Bill is a proposal for law. Stages and readings are steps as it proceeds through Parliament. An Act has received Royal Assent. A statutory instrument is a form of secondary legislation. A treaty is an agreement governed by international law. [How laws are made](https://www.parliament.uk/about/how/laws/) |
| MP, peer, constituency and office | An MP is a Member of the Commons, normally representing a constituency. Members of the Lords may have peerage titles. An office, such as a ministerial post, is a role with a holder and effective dates. Check who held the role on the contribution date. [Find Members](https://members.parliament.uk/) |
| Alias, controlled vocabulary and coverage | An alias is another name for a concept. The vocabulary specifies stable IDs, types and aliases. Coverage shows which dates, Houses and terms were checked. Similar wording can refer to different concepts. |
| Department, public body, regulator and committee | A department covers part of government business. A public body performs public functions. A regulator oversees activity in a specified area. A parliamentary committee examines subjects or scrutinises government and legislation. |
| Organisation, place and subject | Organisations include companies, public bodies, associations, broadcasters, governments and international institutions. Places include territories, nations, countries, regions, counties, cities, towns and constituencies. Subjects describe policy areas. The [controlled vocabulary](../profile/vocabulary.yaml) gives the site's precise identifiers, names, aliases and source links where supplied. |
| Programme, review, digital service and infrastructure | A programme groups activities towards an objective. A review examines a question or area of policy. A digital service supports a task through software. Infrastructure is the equipment or facilities that support an activity. The vocabulary also records technologies used within services. |

## Try the topics

- **Synergy programme** concerns shared corporate services, including finance and HR, for participating departments. Follow the Westminster Hall contribution links and the later pension debate to distinguish statements about the programme from statements about pensions. [Worked evidence and scope](https://chris-page-gov.github.io/okf-hansard/november/ask.html)
- **Microsoft 365** is a suite of productivity and collaboration services. The statement raises digital resilience, which concerns continuing or recovering service when systems fail. [Outage statement companion](https://chris-page-gov.github.io/okf-hansard/voice-microsoft-365.html)
- **NHS Federated Data Platform** is NHS England's platform for bringing specified operational data together. The Commons example concerns the platform and its supplier; questions about use and safeguards need the source wording and scope. [NHS England's platform overview](https://www.england.nhs.uk/digitaltechnology/nhs-federated-data-platform/) · [Companion examples](https://chris-page-gov.github.io/okf-hansard/demo.html)
- **NEET** means not in education, employment or training. Hansard records discussion. Use the ONS definitions and publication dates when quoting official population estimates. [ONS NEET series](https://www.ons.gov.uk/employmentandlabourmarket/peoplenotinwork/unemployment/datasets/youngpeoplenotineducationemploymentortrainingneettable1)
- **Data centres** house computing, storage and networking equipment. The topic can appear in debates on AI, planning, electricity demand or digital resilience. Choose the appropriate terms before comparing the distribution of mentions. [Contribution timeline](https://chris-page-gov.github.io/okf-hansard/november/history.html)

## Learn the technical terms

| Term | Meaning |
| --- | --- |
| AI assistant, context and grounding | An assistant writes or speaks with you. Context is the information available to it for the question, such as your preference or conversation. Grounding means supplying relevant, inspectable evidence for the answer. |
| Voice chat, dictation and saved preference | Voice chat is a spoken conversation. Dictation transcribes your words into text. A saved preference can tell a supporting assistant how to interpret a short phrase in a later chat. |
| API, MCP, host and connector | An application programming interface lets software ask for data or an action. The Model Context Protocol is a shared convention for assistants to discover and use tools and resources. The app you use is the host. Its client connection reaches the server that serves the data. |
| Agent Skill, resource and tool | A skill describes how to carry out a task. An MCP resource is content a host can read. A tool accepts structured inputs and returns a result. A skill can tell the assistant which tool or resource to use. |
| Transport, stdio, HTTP and HTTPS | A transport carries messages. Stdio uses the input and output streams of a local process. HTTP uses network requests. HTTPS encrypts the network link and proves the server's domain identity to a client that checks its certificate. |
| JSON, YAML, schema and contract | JSON and YAML are ways to write structured information. A schema defines the valid shape of a file. A contract also records how a producer and reader use that shape, with checks for the behaviour they rely on. |
| OAuth, scope and token | OAuth lets an app act within a granted scope, which describes its permissions. An access token carries that grant to a service. A model token is a piece of text used to measure AI input or output. These are different uses of the word token. |
| Static site, Git branch and pull request | A static site serves published files. A Git branch names a line of changes. A pull request proposes changes to another branch and records review and automated checks. GitHub Pages serves files from this project's generated publication branch. |
| Cache, backfill and receipt | A cache reuses previously fetched or computed material. Backfill adds historical evidence. A receipt records the inputs and result of a completed check or operation so it can be verified later. |
| Deterministic processing and inference | Deterministic code uses rules that can be replayed against fixed inputs. Inference is the generation or prediction performed by an AI model. The scheduled capture, matching and publication use deterministic code. Your own assistant can apply inference to the evidence you choose. |

## Bring your own AI

The site publishes evidence and ways to inspect it. A personal assistant can choose relevant public questions using context it already holds, retrieve the necessary evidence and speak the answer. The user can avoid combining private context with public requests by giving the assistant a rule to send only approved topics and dates. A product may still transmit requests, excerpts and interaction data under its own settings. The [mobile demonstration](mobile-demonstration.md) explains collection access, the portable skill, the signed-in case and how to check which route was used.
